# Math Mastery Hub — Agent Instructions

## Mandatory brand review for frontend work

Before planning, creating, or editing **any frontend-facing UI** (including the landing page, styles, templates, components, course cards, student screens, and light/dark themes):

1. **Read `docs/brand/BRAND_GUIDELINES.md` in full** and follow the approved Math Mastery Hub visual identity.
2. Treat the **user-approved landing-page mockup** as the official visual reference. If the mockup is not available in the task context, request it rather than inventing a replacement.
3. Follow the documented **DM Sans / DM Serif Display / IBM Plex Mono** type hierarchy, light/dark color palettes, corner radii, existing logo, real course covers, and consistent icon styling.
4. Preserve current page structure, section order, content, and functionality unless the user explicitly authorizes changes. Do not invent features, claims, imagery, or visual decoration.
5. Reuse existing assets and components. Do not add an unnecessary design layer, duplicate style system, or unrelated refactor.
6. For any approved UI implementation, check **both light and dark modes**, mobile and desktop layouts, contrast, interaction states, and fidelity to the approved mockup.
7. If an existing implementation conflicts with the approved brand guide, **surface the conflict and request a scoped decision**; do not silently rewrite shared design tokens.

## Current phase — documentation only

The approved mockup and `docs/brand/BRAND_GUIDELINES.md` establish the direction, **not permission to implement it**. Do not change site code, CSS, templates, layout, routes, backend, or production behavior until a separate implementation request is approved.

These instructions supplement any other applicable repository rules; do not remove or override unrelated project instructions.
